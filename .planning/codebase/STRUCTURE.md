## Directory Purposes

**`firmware/src/`:**
- Purpose: All ESP32 firmware source code
- Contains: 3 source files + 1 header
- Key files: `moodlight.cpp` is the monolithic main file containing web server, MQTT, LED control, and all business logic

**`firmware/data/`:**
- Purpose: Web interface files uploaded to ESP32 LittleFS filesystem
- Contains: HTML pages, CSS, JavaScript
- Uploaded separately from firmware via `pio run -t uploadfs` or OTA `.tgz` upload
- Served by ESP32 WebServer on port 80

**`sentiment-api/`:**
- Purpose: Complete backend service (Python Flask + Docker stack)
- Contains: Application code, database schema, Docker configuration
- Deployed to `server.godsapp.de` at `/opt/auraos-moodlight/sentiment-api/`

**`releases/`:**
- Purpose: Pre-built release artifacts for OTA updates
- Contains: Firmware binaries and UI archives
- Generated by: `./build-release.sh`
- Committed to git

**`docs/`:**
- Purpose: Project documentation with screenshots
- Contains: GitHub Pages site with UI screenshots

## Naming Conventions

**Files:**
- Firmware source: PascalCase for utility files (`MoodlightUtils.h`), lowercase for main (`moodlight.cpp`, `config.h`)
- Backend Python: snake_case (`background_worker.py`, `moodlight_extensions.py`)
- Web interface: lowercase (`index.html`, `setup.html`, `mood.html`)
- CSS/JS: lowercase matching their HTML page (`mood.css`, `mood.js`, `setup.js`)

**Directories:**
- All lowercase (`src/`, `data/`, `js/`, `css/`)
- PlatformIO convention directories: `include/`, `lib/`, `test/`

## Where to Add New Code

**New Firmware Feature:**
- If it's a utility/helper: Add class to `firmware/src/MoodlightUtils.h` and `firmware/src/MoodlightUtils.cpp`
- If it's application logic: Add to `firmware/src/moodlight.cpp` (note: this file is already very large)
- New web page: Create `.html` in `firmware/data/`, JS in `firmware/data/js/`, CSS in `firmware/data/css/`
- New web server route: Add `server.on(...)` call in `setupWebServer()` section of `firmware/src/moodlight.cpp` (around line 1865)
- New HA entity: Declare global in `firmware/src/moodlight.cpp` (around line 104), configure in `setupHA()` (line 3282)

**New Backend API Endpoint:**
- Device-facing endpoints: Add to `sentiment-api/moodlight_extensions.py` inside `register_moodlight_endpoints()`
- Admin/internal endpoints: Add to `sentiment-api/app.py`
- New database operations: Add methods to `Database` class in `sentiment-api/database.py`
- Schema changes: Modify `sentiment-api/init.sql` (note: only runs on first container start)

**New Configuration Value:**
- Firmware compile-time: Add `#define` to `firmware/src/config.h`
- Firmware runtime: Add to `saveSettingsToFile()` / `loadSettings()` in `firmware/src/moodlight.cpp`
- Backend: Add environment variable to `sentiment-api/docker-compose.yaml` and `sentiment-api/.env.example`

**New Release:**
- Run `./build-release.sh` from project root
- Artifacts placed in `releases/vX.X/`

## Web Server Routes (Firmware)

The ESP32 web server exposes these route groups (all defined in `firmware/src/moodlight.cpp`):

**Pages (serve HTML from LittleFS):**
- `GET /` -> `index.html`
- `GET /setup` -> `setup.html`
- `GET /mood` -> `mood.html`
- `GET /diagnostics` -> `diagnostics.html`

**Static Assets:**
- `GET /css/style.css`, `GET /css/mood.css`
- `GET /js/script.js`, `GET /js/mood.js`, `GET /js/setup.js`

**Status & Data APIs:**
- `GET /api/status` - Device status JSON
- `GET /api/stats` - Sentiment statistics
- `GET /api/backend/stats` - Backend statistics (v9.0)
- `GET /api/storage` - LittleFS storage info
- `GET /api/system/metrics` - System health metrics JSON
- `GET /api/system/diagnose` - Full system diagnostics
- `GET /api/system/info` - System information
- `GET /api/firmware-version` - Current firmware version
- `GET /api/ui-version` - Current UI version
- `GET /logs` - Debug log buffer
- `GET /status` - HTML status page

**Settings APIs:**
- `GET /api/settings/all` - All settings as JSON
- `GET /api/settings/hardware` - Hardware pin settings
- `GET /api/settings/api` - API URL settings
- `GET /api/settings/mqtt` - MQTT settings
- `GET /api/settings/colors` - Color configuration
- `GET /api/export/settings` - Export all settings as JSON

**Configuration Actions:**
- `POST /savewifi` - Save WiFi credentials
- `POST /savemqtt` - Save MQTT settings
- `POST /saveapi` - Save API settings
- `POST /savecolors` - Save color configuration
- `POST /savehardware` - Save hardware pin settings
- `POST /factoryreset` - Factory reset
- `POST /resetwifi` - Reset WiFi settings
- `GET /wifiscan` - Scan available WiFi networks

**Control Actions:**
- `GET /refresh` - Trigger manual sentiment update
- `GET /toggle-light` - Toggle LED on/off
- `GET /toggle-mode` - Toggle auto/manual mode
- `GET /set-color?r=&g=&b=` - Set manual LED color
- `GET /set-brightness?value=` - Set LED brightness
- `GET /restart` - Restart device

**OTA Updates:**
- `POST /ui-upload` - Upload UI .tgz file for LittleFS update
- Firmware update handler (around line 2887)

## Backend API Routes

Defined across `sentiment-api/app.py` and `sentiment-api/moodlight_extensions.py`:

**Device Endpoints (moodlight_extensions.py):**
- `GET /api/moodlight/current` - Current sentiment (Redis-cached, device tracking)
- `GET /api/moodlight/history?hours=168` - Sentiment history
- `GET /api/moodlight/trend` - Trend analysis (current vs 24h vs 7d)
- `GET /api/moodlight/stats` - System statistics
- `GET /api/moodlight/devices?hours=2` - Active device list
- `POST /api/moodlight/cache/clear` - Invalidate Redis cache

**Legacy/Admin Endpoints (app.py):**
- `GET /` - Service info
- `GET /api/health` - Health check (DB + OpenAI status)
- `GET /api/news` - Live sentiment analysis (real-time RSS + OpenAI)
- `GET /api/news/total_sentiment` - Legacy device endpoint (reads from DB)
- `POST /api/feedconfig` - Runtime RSS feed configuration
